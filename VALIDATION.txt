CoolTown Planner validation — quality and scenario update

Automated checks: 28 test groups in src/algorithms/planning.test.ts.
Original 23 groups retained: exact optimiser vs independent exhaustive oracle, budgets,
exclusions, exclusivity, ties, objective weighting, solar calculations and suitability,
NDVI/missing observations, GeoJSON validation, future optimisation and JSON export.
Five added groups: coverage boundaries/missing values; all environmental recommendation
rules using coverage and observations; conflicting original roof totals withheld while
optimiser resolves conflict; exported quality policy and conflict status; GIS observed
provenance, coordinates and coverage.

Commands:
  npm.cmd test
  node node_modules/typescript/bin/tsc --noEmit
  npm.cmd run build

The build starts from current source and regenerates dist. BUILD-MANIFEST.json records
SHA-256 hashes of source/config files and all generated dist files for this delivery.
Vite may report a bundle-size warning (>500 kB); this does not prevent a successful build.

Limitations:
- 80% valid coverage is an illustrative configurable rule, not scientific certification.
- All shipped records are synthetic, including 100% demo coverage.
- Solar/site input verification is independent of environmental satellite coverage.
- Conflicting original scenarios have valid:false and metrics:null in JSON; the
  algorithm's numeric placeholders must not be presented as feasible scenario totals.
- Optional GeoJSON map is prepared and TypeScript-checked, not connected to real data.
  Leaflet runtime and CSS are deliberately host-supplied; no external map/API is fetched.
- No claimed satellite authenticity, topology validation, engineering approval, validated
  cooling reduction or machine learning. Exact optimiser supports <=22 eligible options.
Browser smoke checks on the rebuilt production preview:
